1. 앱 만들기 완료

홈 → 앱 만들기 · 여기서 정한 값은 대부분 되돌릴 수 없다

문서에 없던 실측 발견. 앱 만들기 폼에 패키지 이름 입력란이 있습니다 — 과거에는 첫 번들 업로드 시점에 확정되던 값입니다. 준비해둔 가이드에 이 필드가 없어 실측 후 가이드를 고쳤습니다. 화면이 문서보다 항상 옳습니다. Diem은 빌드 applicationId와 동일하게 com.vravio.diem으로 입력했고, 이 값은 생성 후 변경할 수 없습니다.

2. 앱 콘텐츠 선언 완료

정책 및 프로그램 → 앱 콘텐츠 · 심사 제출의 관문, 전부 수동 입력

12개 항목을 위에서 아래로. Diem의 답은 대부분 "아니요"지만(무광고·무수집·무로그인), 선언은 빌드 실제와 일치해야 합니다 — 광고 없다고 선언하고 광고 SDK가 들어 있으면 반려됩니다.

이 단계에서 나온 실수 두 가지 — 다음 앱에서 반복하지 말 것. ① 타겟 연령을 전부 체크(위 캡처). ② 등급 설문 이메일에 개인 주소 입력 — 회사 공개 주소로 통일해야 합니다. 둘 다 제출 전에 잡았습니다.

5.5 비공개 테스트 (Closed/Alpha) 승인·게시됨

테스트 및 출시 → 테스트 → 비공개 테스트 · 2026-08-18 제출 → 같은 날 승인·출시 · 캡처 6장 실측

정정 — 08-13 새벽 "프로덕션 제출 완료" 기록은 오기. 08-18 콘솔 실측 결과 프로덕션 트랙 비활성, 검토 대기·미게시 변경 0건 — 제출이 반영되지 않았습니다. 추정 원인: 게시 개요(Publishing overview)의 "변경사항 검토 제출" 최종 클릭 누락. 재발 방지 확인법: 제출 후 게시 개요에 "검토 중인 변경사항"이 표시되는지 반드시 확인.
  1. 테스터 지정

    테스터 탭에서 기존 목록 '사전테스트'(5명)를 지정하고 저장

  2. 라이브러리에서 App Bundle 3(1.2.0) 추가

    초안 릴리스에 기존 번들을 라이브러리에서 선택 — 재업로드·재빌드 금지. 번들 3 = versionCode 3 · 1.2.0 · targetSDK 36 · minAPI 24 · 다운로드 7.89MB(로컬 AAB 파일 13.1MB)

  3. 출시명 자동 입력 + 출시 노트 "이전 버전에서 복사"

    내부 테스트에서 en+ko 2개 언어 복사

  4. 미리보기 — 경고 1건

    네이티브 디버그 기호 미업로드. 제출 비차단이며 Kotlin 앱은 통상 무시 가능

  5. 게시 개요 → 변경사항 3건 검토 제출

    버전 출시·트랙 재시작·테스터 설정 3건 제출 → 상태 "검토 중인 변경사항". 사전 검사 최대 ~14분 → 심사 큐(통상 7일 이내). 실측(콘솔 표시 시각): 09:31 제출 → 09:44 승인(13분) → 21:33 "변경사항 게시" 클릭(관리형 게시) → 21:47 출시됨 — 심사는 공식 안내보다 훨씬 짧았으나 1회 실측이라 일반화 금지

조직 계정 면제. "테스터 12명 이상 × 연속 14일" 요건은 2023-11-13 이후 생성된 개인 계정 전용 — Vravio Inc는 조직 계정이라 면제. 심사 통과 즉시 프로덕션 승급 가능.
승인 직후 콘솔에 "다음 출시 버전을 위한 발견 항목" 2건. 카테고리 사용자 환경, 비차단. ① Edge-to-edge 인셋 처리(targetSdk 35+) ② Android 15 지원 중단 API setStatusBarColor/setNavigationBarColor 호출. 빌드 경고 "네이티브 디버그 기호 미포함"과 함께 다음 릴리스(versionCode 4)에서 수정 예정. 관리형 게시가 켜져 있어 승인 ≠ 게시 — 실측: 09:44 승인 뒤에도 게시되지 않다가, 21:33 게시 개요 › "관리형 게시가 사용 설정됨" › "변경사항 3개 게시"를 수동 클릭하고 나서야 21:47 출시됨으로 바뀌었다(아래 캡처). 승인 후 설치 0명 — 테스터에게 옵트인 링크 배포가 남았다.

이후 — 발견 항목을 반영한 vc4(1.2.1)를 빌드해 세컨드 폰에서 스모크 테스트한 뒤, 비공개 테스트 재업로드는 건너뛰고 프로덕션에 직접 제출했다(아래 6단계). 계획했던 "동일 번들 3 승격"은 vc4 제출로 대체됐다.

6. 프로덕션 검토 중(08-21 제출)

테스트 및 출시 → 프로덕션 · 2026-08-21 14:23 검토 제출 · 캡처 5장 실측

vc4(1.2.1) AAB를 세컨드 폰에 설치해 스모크 테스트를 마친 뒤, 비공개 테스트 재업로드는 건너뛰고 프로덕션에 바로 제출했습니다. 계획(번들 3 승격)과 달리 새 번들 4를 업로드한 것이라 프로덕션이 비공개 테스트보다 앞선 버전이 됩니다. 승인·게시는 아직 아닙니다.

  1. 국가/지역 — 머리글 전체 선택

    프로덕션 트랙은 국가 0개에서 시작한다(트랙별 독립). 목록 머리글 체크박스로 176개 + "기타 국가"를 일괄 선택 → 저장 › "게시 개요로 이동?" 모달은 "나중에"로 닫고 계속 — "다른 트랙에 영향을 미침" 표시는 게시 개요의 변경 항목에서 확인

  2. 새 버전 만들기

    빈 버전 화면. 공개 트랙이라 업로드 화면에 앱 서명 키 ⓘ가 붙는다(아래 함정)

  3. AAB 업로드 — App Bundle 4(1.2.1)

    라이브러리 승격이 아닌 새 파일 업로드. 타겟 SDK 36 · 신규 설치 7.48MB

  4. 출시 노트 "이전 버전에서 복사"

    en+ko 2개 언어 — 비공개 테스트 때와 같은 절차

  5. 미리보기 — 경고 1건(무시)

    네이티브 디버그 기호 미업로드. .so 사전 strip으로 해소 불가·비차단 → 저장 → "게시 개요로 이동?"

  6. 게시 개요 → 변경사항 3건 검토 제출

    모달 "검토는 일반적으로 7일 이내" → 제출 ID 3 · 14:23 · 프로덕션 · 검토 중(빠른 검사 최대 14분). 첫 프로덕션은 단계적 출시 비율 UI가 없어 전체 출시 100%

국가 선택 — 전 세계 배포로 확정(08-21). 계획(6.1)의 EEA 30국·영국·스위스 제외는 광고(AdMob) 도입을 전제로 한 UMP 동의·GDPR 대비였는데, 1차 빌드는 광고 없음·데이터 수집 0건이라 사유가 소멸했다. 남은 요건은 DSA 판매자 상태 선언(조직 계정 연락처 공개)뿐 — 실측은 머리글 전체 선택(176개 + 기타 국가)으로 저장됐고 그대로 유지한다. 단 v1.3.0에서 광고를 켜면 UMP 구현 전까지 EEA·영국·스위스 제외가 다시 필요하다. 게시 개요의 국가/지역 변경 항목에 "다른 트랙에 영향을 미침" 배지가 붙은 점도 기록해 둔다.
이번에 새로 확인된 함정 두 가지. ① 앱 서명 키 선택은 공개 트랙 게시 후 고정된다 — 업로드 화면 ⓘ가 비가역이라고 명시한다. 프로덕션이 첫 공개 트랙이므로 지금이 마지막 선택 지점. ② 첫 프로덕션에는 단계적 출시 비율 UI가 없다 — 전체 출시 100%로만 나간다. 일부 사용자에게 먼저 풀어보는 건 두 번째 릴리스부터 가능.

7. 심사 대기 중

08-21 14:23 제출 · 빠른 검사 후 검토 대기

  • 현재 — 제출 ID 3이 빠른 검사(최대 14분)를 거쳐 심사 큐에 있다. 공식 안내 "일반적으로 7일 이내". 비공개 테스트는 13분 만에 승인됐지만 1회 실측이라 프로덕션에 일반화하지 않는다. 대기 중 새 버전 제출 금지

  • 게시 후 30분 내 — 스토어 검색·설치·스크린샷 표시 확인
