0. 게시 전 준비 완료

콘솔에 들어가기 전에 끝내둔 것

  • 개발자 계정 — 조직 계정 신원·전화번호 인증. 조직 계정은 개인 계정에 부과되는 "테스터 12명×14일" 의무가 없어 내부 테스트 후 바로 프로덕션 신청이 가능합니다
  • 개인정보처리방침 호스팅 — 자리표시자를 실제 값으로 교체해 GitHub Pages에 게시. 심사자가 실제로 열어보므로 URL이 살아 있어야 합니다
  • 스토어 자산 — 문구(영/한 각 3종), 아이콘 512, 피처 그래픽 1024×500, 스크린샷 8장

1. 앱 만들기 완료

홈 → 앱 만들기 · 여기서 정한 값은 대부분 되돌릴 수 없다

문서에 없던 실측 발견. 앱 만들기 폼에 패키지 이름 입력란이 있습니다 — 과거에는 첫 번들 업로드 시점에 확정되던 값입니다. 준비해둔 가이드에 이 필드가 없어 실측 후 가이드를 고쳤습니다. 화면이 문서보다 항상 옳습니다.

2. 앱 콘텐츠 선언 완료

정책 및 프로그램 → 앱 콘텐츠 · 심사 제출의 관문, 전부 수동 입력

12개 항목을 위에서 아래로. Diem의 답은 대부분 "아니요"지만(무광고·무수집·무로그인), 선언은 빌드 실제와 일치해야 합니다 — 광고 없다고 선언하고 광고 SDK가 들어 있으면 반려됩니다.

이 단계에서 나온 실수 두 가지 — 다음 앱에서 반복하지 말 것. ① 타겟 연령을 전부 체크(위 캡처). ② 등급 설문 이메일에 개인 주소 입력 — 회사 공개 주소로 통일해야 합니다. 둘 다 제출 전에 잡았습니다.

3. 스토어 등록정보 완료

사용자 늘리기 → 앱 정보 → 스토어 등록정보

  • 영어(기본) — 제목 29/30자 · 짧은 설명 73/80 · 자세한 설명 2,185/4,000. 글자수는 입력 전에 전부 실측해뒀다
  • 그래픽 — 아이콘·피처 그래픽·스크린샷 8장, 파일명 번호 순서대로 업로드
  • 한국어 — 번역 추가로 등록. "AI로 번역 가져오기"는 쓰지 않았다 — 준비한 문구가 검색 키워드를 반영한다

4. Play 앱 서명 완료 (첫 업로드 시 자동 등록)

첫 AAB 업로드 때 자동 등록됩니다. 이후 앱 서명 키는 Google이 보관하고, 개발자는 업로드 키만 관리합니다. 업로드 키를 잃어도 재설정 가능해지는 시점이라, 첫 업로드 전 키 보관이 가장 위험한 구간입니다.

5. 내부 테스트 완료 · 08-13

테스트 및 출시 → 테스트 → 내부 테스트 · 심사 없이 즉시 배포

  • 테스터 이메일 목록 → AAB 업로드 → 릴리스 노트 → 출시
  • 참여 링크(옵트인 URL)로 실기기 설치 → 위젯·언어·다크모드 5분 점검

5.5 비공개 테스트 (Closed/Alpha) 승인·게시됨

테스트 및 출시 → 테스트 → 비공개 테스트 · 2026-08-18 제출 → 같은 날 승인·출시 · 캡처 5장 실측

정정 — 08-13 새벽 "프로덕션 제출 완료" 기록은 오기. 08-18 콘솔 실측 결과 프로덕션 트랙 비활성, 검토 대기·미게시 변경 0건 — 제출이 반영되지 않았습니다. 추정 원인: 게시 개요(Publishing overview)의 "변경사항 검토 제출" 최종 클릭 누락. 재발 방지 확인법: 제출 후 게시 개요에 "검토 중인 변경사항"이 표시되는지 반드시 확인.
  1. 테스터 지정

    테스터 탭에서 기존 목록 '사전테스트'(5명)를 지정하고 저장

  2. 라이브러리에서 App Bundle 3(1.2.0) 추가

    초안 릴리스에 기존 번들을 라이브러리에서 선택 — 재업로드·재빌드 금지. 번들 3 = versionCode 3 · 1.2.0 · targetSDK 36 · minAPI 24 · 다운로드 7.89MB(로컬 AAB 파일 13.1MB)

  3. 출시명 자동 입력 + 출시 노트 "이전 버전에서 복사"

    내부 테스트에서 en+ko 2개 언어 복사

  4. 미리보기 — 경고 1건

    네이티브 디버그 기호 미업로드. 제출 비차단이며 Kotlin 앱은 통상 무시 가능

  5. 게시 개요 → 변경사항 3건 검토 제출

    버전 출시·트랙 재시작·테스터 설정 3건 제출 → 상태 "검토 중인 변경사항". 사전 검사 최대 ~14분 → 심사 큐(통상 7일 이내). 실측(콘솔 표시 시각): 09:31 제출 → 09:44 승인(13분) → 21:47 출시됨 — 공식 안내보다 훨씬 짧았으나 1회 실측이라 일반화 금지

조직 계정 면제. "테스터 12명 이상 × 연속 14일" 요건은 2023-11-13 이후 생성된 개인 계정 전용 — Vravio Inc는 조직 계정이라 면제. 심사 통과 즉시 프로덕션 승급 가능.
승인 직후 콘솔에 "다음 출시 버전을 위한 발견 항목" 2건. 카테고리 사용자 환경, 비차단. ① Edge-to-edge 인셋 처리(targetSdk 35+) ② Android 15 지원 중단 API setStatusBarColor/setNavigationBarColor 호출. 빌드 경고 "네이티브 디버그 기호 미포함"과 함께 다음 릴리스(versionCode 4)에서 수정 예정. 관리형 게시가 켜져 있어 승인 ≠ 게시 — 게시 개요 › "관리형 게시가 사용 설정됨" › 변경사항 게시까지 확인. 승인 후 설치 0명 — 테스터에게 옵트인 링크 배포가 남았다.

다음 단계 — 프로덕션 승급(STEP 0 재확인 후): 국가/지역 선택(아래 6단계), 동일 번들 3을 라이브러리에서 추가, 게시 개요 제출까지 완료 확인.
