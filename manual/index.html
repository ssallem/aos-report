STEP 0. 사전 준비 실측 완료

콘솔에 들어가기 전에 끝낸다 — 하나라도 없으면 중간에 멈춘다

  • 개발자 계정 — 조직 계정 권장. "테스터 12명 × 연속 14일" 비공개 테스트 의무는 2023-11-13 이후 생성된 개인 계정 전용이라 조직 계정은 면제(실측 확인). 계정 상태가 "확인됨(Verified)"이어야 게시 가능
  • 전화번호 인증 — 인증 완료 전에는 "첫 번째 앱 만들기"가 활성화되지 않는다
  • keystore 생성·백업 — 업로드 키를 만들고 오프사이트 포함 2곳 이상 백업. 비밀번호는 키 파일과 다른 곳(비밀번호 관리자)에. Play 앱 서명 덕에 분실해도 재설정은 가능하지만, 첫 업로드 전 구간이 가장 위험하다
  • 개인정보처리방침 HTML 호스팅 — GitHub Pages로 충분(실측). 조건: HTTPS · 로그인 없이 접근 · 자리표시자([연락 이메일] 등) 0건. 연락처는 [공개 연락용 회사 이메일]로 — 스토어·심사에 공개된다
  • 스토어 자산 — 아이콘 512×512 PNG · 피처 그래픽 1024×500 · 폰 스크린샷 1080×2160(2:1) 최소 2장 [예시: Diem 8장]
  • 서명된 AAB — bundleRelease 빌드 후 jarsigner -verify로 "jar verified" 확인. 유닛 테스트 전체 통과가 선행 조건 [예시: Diem 79개 PASS · AAB 12.54MB]

사용자 늘리기(성장) → 스토어 현황 → 기본 스토어 등록정보

문구한도비고

간단한 설명80[예시: Diem 73/80]

  • 글자수는 입력 전에 실측해 두고, 리스팅 문서(PLAY_LISTING.md)의 확정 블록을 복붙용 .txt로 추출해 그대로 붙여넣는다 — 콘솔에서 즉석 수정하면 검증된 글자수·키워드가 깨진다
  • 그래픽 — 아이콘·피처 그래픽·스크린샷을 파일명 번호 순서대로 업로드

STEP 4. 내부 테스트 실측 완료

테스트 및 출시 → 테스트 → 내부 테스트 · 심사 없이 즉시 게시되는 유일한 트랙

  1. 테스터 이메일 목록 만들기

    테스터 탭 → 목록 이름 + 테스터의 Google 계정 이메일 → 저장

  2. 새 버전 만들기 → AAB 업로드

    ⚠️ 실측: 드래그 업로드는 릴리스 마법사 1단계(업로드 영역)에서만 동작한다. 2단계(미리보기)로 넘어간 상태에서 드래그하면 아무 반응이 없다 (08-13 실측 사고 — 1단계로 돌아가 해결)

  3. 출시 노트

    <en-US> 블록 형식으로 입력(화면 안내 따름). 추가 언어는 <ko-KR> 등 블록 추가

  4. 출시 → 즉시 게시

    내부 테스트는 심사 없이 수 분 내 반영

  5. 옵트인 링크로 실기기 설치

    테스터 탭의 참여 링크를 테스터에게 전달 → "테스터 되기" 수락 후 Play 스토어에서 설치(사이드로드 아님) → 핵심 기능 5분 점검

실측 — 미검토 상태의 스토어 표시는 이렇게 보이는 게 정상. 앱명이 패키지명 + "(unreviewed)"로 표기되고 아이콘이 회색이며 17+ 배지(미등급 = 고연령 취급)가 붙는다 — 첫 심사 통과 전 정상 (08-13~17 실기기 관측). 심사를 통과하면 정상 표시로 바뀐다 — 이 단계에서 고칠 것이 아니다.

STEP 5. 비공개(Closed) 테스트 실측 완료 · 08-18

테스트 및 출시 → 테스트 → 비공개 테스트 · 2026-08-18 실측 5단계

  1. 테스터 목록 지정

    테스터 탭에서 이메일 목록 선택·저장. "게시 개요로 이동하시겠어요?" 팝업(08-18 캡처 실측)은 나중에 — 릴리스 작업을 먼저 끝낸다 [예시: Diem 기존 목록 5명]

  2. 라이브러리에서 App Bundle 추가

    같은 versionCode는 재업로드 불가 — 재빌드 금지. 내부 테스트에 올린 검증된 번들을 "라이브러리에서 추가"로 선택한다 [예시: Diem 번들 3 = 1.2.0]

  3. 출시명 자동 입력 + 출시 노트 "이전 버전에서 복사"

    내부 테스트 버전에서 노트 복사 → 등록된 언어가 한 번에 넘어온다 [예시: Diem en+ko 2개]

  4. 미리보기 — 경고 확인

    "네이티브 디버그 기호 미업로드" 경고는 제출 비차단(Kotlin 앱 통상 무시 가능). 광고 ID 불일치·서명 경고가 뜨면 그 자리에서 해결

  5. 게시 개요 → "변경사항 검토 제출"까지

    여기까지 눌러야 심사 큐에 들어간다. 제출 후 게시 개요에 "검토 중인 변경사항"이 표시되는지 확인. 사전 검사 최대 ~14분 → 심사(통상 7일 이내)

STEP 6. 프로덕션 추가 예정 — 승인 후 실측 기입

비공개 테스트 심사 통과 후 진행 · 아래는 뼈대, 실측하면서 채운다

  • 국가/지역 선택 — "모든 국가/지역 추가" 후 EEA 30국 + 영국 + 스위스 제외. 사유: 광고 도입 대비 GDPR 동의폼(UMP) 미구현. 최초 1회만 수동, 이후 상속
  • 라이브러리에서 동일 번들 — 테스트를 통과한 그 번들을 승격. 재빌드 금지
  • 게시 개요 제출 확인 — "출시 시작"만으로 끝나지 않는다. 게시 개요에서 검토 제출 → "검토 중인 변경사항" 표시 확인

#함정대응 · 확인법
1"출시 시작" 클릭만으로는 제출되지 않는다 — 게시 개요의 최종 제출 누락으로 5일을 허비한 실사고. 심사가 시작조차 안 됐다제출 후 게시 개요에 "검토 중인 변경사항" 표시 확인. 없으면 미제출
2versionCode는 1회용 — 같은 코드 재업로드는 거부된다같은 버전 재사용은 "라이브러리에서 추가"로만. 새 빌드는 versionCode +1
3"테스터 12명 × 14일" 규칙은 개인 계정 전용 — 콘솔·확장 프로그램이 조직 계정에도 경고를 띄울 수 있다조직 계정은 면제(2023-11-13 이후 개인 계정에만 적용). 계정 유형부터 확인
4미등급 앱 = 17+ 배지 — 심사 전 스토어 표시가 이상해 보인다미검토 상태의 정상 동작(미등급 = 고연령 취급). 심사 통과 후 자동 정상화
5드래그 업로드 위치 함정 — 2단계(미리보기)에서 드래그하면 무반응 (08-13 실측 사고)1단계(업로드 영역)에서만 동작 — 1단계로 돌아가 해결
6타겟층 전 연령 체크 → 가족 정책 발동 — 12세 이하 포함 시 별도 심사가 통째로 붙는다"만 18세 이상" 단독 권장. 스토어 노출·검색에는 영향 없음
7IARC 설문 이메일에 개인 주소 입력 — 등급 인증서 수신 주소가 노출 경로가 된다[공개 연락용 회사 이메일]로 통일. 방침·스토어 연락처와 같은 주소
8공개 git 리포에 개인 이메일로 커밋 — 전역 git 설정이 개인 계정이면 공개 리포에 그대로 박힌다커밋 전 리포별 identity 확인: git log -1 --format="%an %ae". 리포 로컬 config로 회사 계정 고정
